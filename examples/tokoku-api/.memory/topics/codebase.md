Tokoku API has two processes from one code base. The API (`src/server.ts`, built in `src/app.ts`)
answers the tablets and the owner's web dashboard. The worker (`src/jobs/worker.ts`) runs background
jobs from BullMQ queues in Redis: the nightly settlement, stock alerts and WhatsApp notifications.

A sale shows the usual path. `POST /sales` arrives in `src/routes/sales.ts`, which validates the body
with Zod and calls `createSale()` in `src/services/sales.ts`. That function checks stock, prices the
items with `src/services/pricing.ts` and saves the sale and its stock movements in one Prisma
transaction; stock changes through `adjustStock()` in `src/stock/adjust.ts`, which also writes
a row to the stock ledger. Card and QRIS payments are confirmed later by the gateway's webhook
(see topics/payments.md).

Payments, returns, purchase orders and stock each have a folder under `src/` with their logic, while `src/routes/` stays thin. Shared helpers live in `src/lib/`: `money.ts` (whole-rupiah
amounts), `db.ts` (the Prisma client) and `logger.ts` (pino). Start reading at `src/app.ts`, then
`src/services/sales.ts`.

- `src/routes/` — Express routers, one file per URL prefix; validate with Zod, then call the area's code.
- `src/services/` — sales and pricing, the code used by the till.
- `src/payments/` — gateway client and webhook; `settlement/` holds the daily payout (frozen, see decisions.md).
- `src/returns/`, `src/purchase-orders/`, `src/stock/` — one folder per business area; new logic for an area goes in its folder.
- `src/jobs/` — queue definitions (`queues.ts`) and the worker entry point; a new background job is added in both.
- `src/lib/` — money, database client, logger; add a helper here once two areas need it.
- `prisma/` — `schema.prisma`, migrations and the seed script.
- `tests/` — Vitest, one folder per area, against the `tokoku_test` database (see gotchas.md).
- `scripts/` — one-off maintenance scripts, run by hand with `npx tsx`.
