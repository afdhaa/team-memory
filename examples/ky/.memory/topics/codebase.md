# Codebase

## How it fits together
The public API is built in `source/index.ts`: `createInstance()` makes the `ky` function, one shortcut per entry of `requestMethods` in `source/core/constants.ts` (`get`, `post`, `put`, `patch`, `head`, `delete`, `query`), `ky.create()`, `ky.extend()`, `ky.stop` and `ky.retry()`. Instance defaults and per-call options are deep-merged by `validateAndMerge()` in `source/utils/merge.ts`. Errors thrown while setting up a request become a rejected promise, not a synchronous throw.

Every request goes through `Ky.create()` in `source/core/Ky.ts`. It runs the `init` hooks on a copy of the options, then the `Ky` constructor validates options, normalizes `retry` (`source/utils/normalize.ts`), resolves `prefix` and `baseUrl`, and builds the `Request`. The returned promise carries the body shortcuts (`.json()`, `.text()`, …); they can still set the `Accept` header because `#run()` waits one microtask before the first hook.

`#run()` drives one request: `beforeRequest` hooks, then `#fetch()` (per-attempt `timeout` via `source/utils/timeout.ts`, raw network failures wrapped as `NetworkError`), then `afterResponse` hooks. After the `afterResponse` hooks, a non-2xx response becomes an `HTTPError` whose `data` holds the read error body, unless `throwHttpErrors` says not to throw or the response is opaque. Fetch failures, those `HTTPError`s and a `ky.retry()` from an `afterResponse` hook go to `#retryFromError()`, which computes the wait, runs `beforeRetry` hooks and fetches again; any other error thrown by a hook is not retried. Errors that end the request pass through `#throwProcessedError()`, which runs `beforeError` hooks, except non-`Error` throws, a new error thrown by a `beforeRetry` hook, and errors while setting up the request (option validation, `init` hooks), which reject without running them. Retry decisions and waits: topics/retries.md.

Supporting code: `source/core/retry-timing.ts` reads `Retry-After` and rate-limit headers; `source/utils/body.ts` handles progress streams, `maxResponseSize` and body cancellation; `source/errors/` holds the error classes; `source/types/` holds the public types and their JSDoc. Start reading at `source/index.ts`, then `Ky.create()`, the constructor and `#run()` in `Ky.ts`.

Code comments in `Ky.ts` often state why a branch exists (usually a runtime quirk or a bug the branch prevents; issue numbers appear in `constants.ts`, not in `Ky.ts`); read them before changing that branch. Values that must be recognised across a duplicated copy of Ky carry a brand, not only a class: `Symbol.for('ky.stop')`, the `isRetryMarker` getter, and the `isKyError` getter that the type guards in `source/utils/type-guards.ts` check.

## Project layout
- `source/index.ts` — public entry point and the list of exports; a new public function, error or type is exported here.
- `source/core/` — `Ky.ts` (the request pipeline), `constants.ts` (method list, option registries, `ky.stop`, `ky.retry()`), `retry-timing.ts` (retry header parsing).
- `source/utils/` — helpers for `Ky.ts`: option merging, retry defaults and validation (`normalize.ts`), timeout, delay, body streams, type guards, network-error detection.
- `source/errors/` — error classes; `HTTPError`, `NetworkError`, `TimeoutError`, `ResponseSizeError` and `ForceRetryError` extend `KyError`, while `SchemaValidationError` and the internal `NonError` extend `Error`.
- `source/types/` — option, hook and response types; option documentation lives in their JSDoc and in `readme.md`.
- `test/` — ava tests named by feature (`retry.ts`, `hooks.ts`, `headers.ts`, …); most start a local Express server with `createHttpTestServer()` from `test/helpers/`, and `test/browser.ts` drives Playwright against the built `distribution/`.
- `test-d/` — type tests compiled by `tsc --project tsconfig.test.json`; they import `ky`, which resolves to `distribution/`.
- `readme.md` — the user documentation of options, hooks and errors.
